# CS336 Lecture 3 学习笔记

> 主题：从“能跑的 Transformer”到“现代可训练、可部署的 LLM 配方”

如果说 Lecture 2 教你怎么给训练算账（FLOPs、显存、MFU），那 Lecture 3 就是在回答另一个更现实的问题：

**同样是 Transformer，为什么现在的模型长得都不太一样？它们到底改了什么，又为什么这么改？**

这篇笔记按模块整理，尽量用“工程直觉 + 最小公式”讲清楚。

---

## 1) 先定基调：Lecture 3 不是“唯一正确答案”

这节课最重要的思维不是背某个结构，而是理解 tradeoff：

- 稳定性 vs 速度
- 效果 vs 成本
- 长上下文能力 vs 推理延迟

所以后面每个模块都可以理解成：

**在质量、稳定、算力、显存之间做结构化取舍。**

---

## 2) Norm 设计：Pre-norm vs Post-norm

设子层函数是 `F(x)`（可以是 attention 或 FFN）。

- Post-norm: `y = LayerNorm(x + F(x))`
- Pre-norm: `y = x + F(LayerNorm(x))`

### 为什么现代 LLM 常用 pre-norm

直觉是梯度路径更顺，深层训练更稳，调参更省心。

在大模型语境下，很多团队的默认起点会是 pre-norm。

---

## 3) LayerNorm vs RMSNorm：为什么大家越来越爱 RMSNorm

LayerNorm 和 RMSNorm 的核心差别：

- LayerNorm：减均值 + 按方差缩放
- RMSNorm：不减均值，只按均方根缩放

RMSNorm 常见写法：

- rms = sqrt((1/d) * sum(x_i^2) + eps)
- y_i = gamma_i * x_i / rms

其中 `eps` 是很小的正数，用来防止除零和数值不稳定。

### 为什么常选 RMSNorm

- 操作更简单
- 工程实现/优化更友好
- 在现代 LLM 配方里效果通常不差

这也是很多模型里常见 `pre-norm + RMSNorm` 组合的原因。

---

## 4) 激活与 FFN：从普通激活到 GLU 门控

普通 FFN（简化）：

- h = act(x * W1)
- y = h * W2

GLU 风格 FFN（简化）：

- a = x * Wa
- g = act(x * Wg)
- h = a * g
- y = h * Wo

### 直觉

`g` 是一个门：

- g_i 小 -> 这一维信息被抑制
- g_i 大 -> 这一维信息被放行

所以 GLU 类方法通常带来更灵活的通道控制，现代 LLM 很常见。

---

## 5) 层组织：Serial vs Parallel

### Serial（串行）

先 attention，再 FFN，层层串起来。

### Parallel（并行）

attention 分支和 FFN 分支并行算，再合并。

两者没有绝对赢家，关键看目标：

- 要稳妥、生态成熟：常见 Serial
- 要探索吞吐/结构折中：可试 Parallel

---

## 6) RoPE：位置编码的“旋转派”

这块是 Lecture 3 高价值模块。

### RoPE 不是加到原 embedding 上

这点非常关键。

- 绝对位置编码常是：`x = token_embedding + pos_embedding`
- RoPE 通常是：对 `Q/K` 做位置相关旋转

即：

- Q_p = R(theta_p) * Q
- K_t = R(theta_t) * K

然后再做 attention：

- score(p,t) = dot(Q_p, K_t)

### 为什么两两分组

因为 RoPE 基于 2D 旋转，旋转公式天然是两维一组：

- x' = x*cos(theta) - y*sin(theta)
- y' = x*sin(theta) + y*cos(theta)

所以把 `head_dim = D` 拆成 `(x0,x1), (x2,x3), ...` 来旋转。

### 为什么用 sin/cos

- 数学上正好表达旋转
- 旋转保范数，数值更稳
- 点积自然带入相对位置信息
- 工程实现成熟，成本低

---

## 7) 超参数共识：不是铁律，是高概率起点

Lecture 3 对超参的态度很实用：

先用共识，再做小范围实验。

关键联动关系：

- model_dim = num_heads * head_dim
- ffn_dim = multiplier * model_dim

### vocab size 的权衡

- 词表太大：`V * d` 参数和输出层计算成本变高
- 词表太小：token 变碎，序列更长，attention 成本上升

这是“参数效率 vs token 效率”的折中。

### dropout / weight decay 的实践倾向

- 大规模预训练里 dropout 常偏小甚至接近不用
- weight decay 常保留，但要和学习率、batch 一起联调

简化更新直觉：

- w <- w - lr * grad - lr * wd * w

---

## 8) 稳定性技巧：很多训练问题其实是数值问题

高频风险点在 softmax 前的 logits。

### 常见现象

- logits 过大 -> softmax 过尖（接近 one-hot）
- 梯度异常、loss spike、训练不稳

### 常见手段

1. 输出层稳定手段（如 z-loss 思路）
2. 注意力侧稳定手段（如 QK norm）
3. logit soft-capping（软截顶）

soft-capping 直觉：

- 对极大值平滑压缩，不是硬截断
- 保留大体排序，抑制极值引发的数值风险

---

## 9) 注意力效率变体：MHA / GQA / MQA + 局部注意力

这是最工程化的一块。

### 9.1 为什么标准 MHA 成本高

长上下文下主要有两块压力：

- 计算：attention 分数是 `L * L`，复杂度随 `L^2` 增长
- 内存/带宽：KV cache 随上下文增长，读写压力很大

### 9.2 MHA vs GQA vs MQA

设：

- num_q_heads = H
- num_kv_heads = H_kv

三者区别本质是 `H_kv`：

- MHA: `H_kv = H`（不共享）
- GQA: `1 < H_kv < H`（分组共享）
- MQA: `H_kv = 1`（最大共享）

所以：

- MHA 质量上限常更稳，但最贵
- MQA 最省 KV 成本，但可能有质量回归
- GQA 是最常见折中

### 9.3 Local / Sliding / Interleaved

- local/sliding：每个 token 只看窗口内邻居
- sparse：广义上是非全连接模式
- interleaved：部分层 full，部分层 local，按层交错

例如：

- full, local, local, full, ...

含义：

- 用少量 full 层保全局信息流
- 用更多 local 层降总体成本

---

## 10) 一个“现代 LLM 配方”直觉

如果你要从零起一个稳妥 baseline，可以把 Lecture 3 思想压缩成：

- pre-norm
- RMSNorm
- GLU 类 FFN
- RoPE
- GQA
- 必要时加稳定性 trick（QK norm / soft-capping 等）

然后再围绕任务和资源做增量实验。

---

## 11) 我自己的 take-away

Lecture 3 给我的最大启发不是“哪种结构最强”，而是：

**架构设计其实是资源约束下的系统工程。**

你要做的是：

1) 先选一个高成功率默认配方
2) 明确你最在意的瓶颈（质量 / 速度 / 显存 / 延迟）
3) 有目的地改一两个模块，做可解释对比

这比“追最新名词”更容易做出能落地的模型。

---

## 12) 一页速记

- pre-norm 通常更稳
- RMSNorm 常见于现代 LLM
- GLU 提供门控表达能力
- RoPE 作用在 Q/K，不是直接加到 embedding
- softmax 稳定性是大模型训练关键风险点
- GQA 常是效率和效果折中首选
- interleaved attention 是长上下文常见工程折中
